# Bangladesh daily source coverage

The daily GitHub ingestion workflow is scheduled at 00:30 UTC / 06:30 Asia/Dhaka. GitHub may start scheduled jobs late; this is a scheduled target, not a real-time guarantee. A push changing the Bangladesh adapters also runs an initial collection. Existing per-user Job Alert import remains available for sources requiring user/provider access.

## Private employers (career pages and job boards)

Private-sector jobs are the main audience, so private sources come first:

- `scripts/ingest/bd/companies.ts` lists established private employers (banks and finance, telecom and IT, e-commerce, manufacturing and groups, health and education, NGOs, multinationals). Each ingest run checks up to 25 of them with `scripts/ingest/bd/discover.ts`: the home page, then the careers link on the same site (subdomains count), honouring robots.txt on every page and following redirects hop by hop. A linked or redirected public job board (SmartRecruiters, Workable, Lever, Greenhouse, Recruitee, Ashby) becomes a board source; JobPosting data on the careers page, or on one confirmed job page under it, makes the company's own page a `jsonld` source. Otherwise the reason is stored (`no_public_feed`, `lists_on_bdjobs`, `unreachable`). Each company has one directory row (`kind = jsonld`, `board_token = dir:<site>`); inactive ones are rechecked weekly. To list them: `select company, last_status, last_error, url from ingestion_sources where board_token like 'dir:%' order by last_status, company;`
- A board token ending in `@bd` (e.g. `DeliveryHero@bd`) reads a multinational's global board for its Bangladesh jobs only. Jobs are placed by their own stated location, never by the source's country, so remote and foreign roles stay out; SmartRecruiters is asked with `country=bd`. Boards confirmed by real Bangladesh postings are in `BD_EMPLOYER_BOARDS` and are registered once.
- Held circulars whose titles name a public body (ministry, directorate, board, forces, state banks...) are read after private ones (`scripts/ingest/bd/sector.ts`), so the daily AI budget goes to private jobs first. Nothing is dropped.
- bdRecruit pages as `/bdjobs/page/N/` (`pagePath` in the registry); its job pages are `/job/<slug>/`.

## Data integrity and cost

- Fetch public pages only, check robots on the configured host, reject external redirects, cap responses, throttle requests and persist a pagination cursor. First-page refresh runs every day while older pages are revisited over successive runs.
- Parse structured JobPosting and explicit labelled circular fields without paid AI calls. Ignore expired jobs. Articles lacking trustworthy position/employer/deadline evidence remain outside matching.
- A conservative identity (employer, role, location, deadline and category) merges a hiring round across sources. Missing deadlines/confidential employers use source-specific identity to avoid joining unrelated jobs. Exact duplicate identity is transactional; no fuzzy claim of universal duplicate removal.
- Keep each discovery URL and any explicit employer/original circular URL. Users can see provenance on the job page.
- Failed detail pages are persisted for next-run retry. Listing outages and partial failures appear as errors and trigger the existing failure notification. A failed or empty fetch never retires the entire source's jobs.
- Image/PDF circulars and ambiguous multi-role newspaper pages are queued in Admin > Circulars awaiting review. Each daily run reads held listing-page circulars, newest first (up to `BD_CIRCULAR_AI_LIMIT`, default 200, 0 turns it off). Image circulars are first read for free: Tesseract OCR (Bangla + English) reads the image, and the vacancy is published when the page's labelled employer, post and deadline are confirmed in the OCR text; the OCR text becomes the vacancy details. Only what that cannot confirm is read with AI (from the free OCR text when it reads cleanly, from the image otherwise; failed AI calls count against the budget too), until the day's AI budget `BD_CIRCULAR_AI_BUDGET_USD` (default $0.50, 0 = free reading only) is spent. Both are GitHub Actions variables (`scripts/ingest/bd/circulars.ts`): the circular image is transcribed, then turned into vacancies. A vacancy is published only when it names an identifiable employer, matches the post named on the listing page, has a current deadline that agrees with the page, shows no fake-job warning signs and passes the same source quality checks as other listings. Everything else stays in review with its reason. Whole e-paper pages and PDFs are not read this way (one page carries many employers' adverts). Each document is tried at most twice.
- RLS protects internal canonical identities and review documents. Only the service role may invoke public-job ingestion; authenticated users may read source occurrences for visible jobs.

## Validation

Disposable PostgreSQL tests replay migrations and check service-only ingestion, cross-portal identity, provenance visibility, expired-job rejection and restricted review data. Parser/fetch tests cover Bengali dates, impossible dates, structured deadlines, ambiguous articles, same-host discovery, cursor resumption, failed-page persistence, robots denial and off-host redirects. CI and production deployment include build checks; deployment also verifies `/api/health`.
